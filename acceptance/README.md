# Retained acceptance evidence

This directory retains historical snapshots, raw records, portable packages, and
package-specific verifiers. Their paths/hashes describe the executions that
actually occurred; source reorganization does not rewrite them.

The active FIFO bundle harness moved to
[`asics/fifo_demo/verif/bundle/`](../asics/fifo_demo/verif/bundle/).
Current feature drivers live under `tooling_acceptance/` and
`integration/workbench/`. See the [layout map](../docs/repository_layout.md).

All child directories are data-only to Dune: captured old `dune` files must not
turn historical source snapshots into active build targets. Retained evidence is
also excluded from Workbench's authored-source copy closure.
Generated Dune trees and installed tooling instead belong in ignored local stores.

## What the packages contain

These are records that a feature worked against real emitted designs or native
tools, rather than the reusable tests that generate those records. A package may
contain command receipts, input/source copies, reports, checksums, replay models,
logs, and unsuccessful attempts retained for comparison.

The directory has accumulated both curated committed packages (about 163 MB) and
much larger local raw captures. Its name does not mean every generated byte should
be committed, nor that every byte can be regenerated identically or safely deleted.

## Retention and staging policy

Raw per-attempt directories are retained locally but ignored by Git using the
root rule `/acceptance/*/*/`. This directory-level boundary lets ordinary Git
discovery and staging prune captured runs, nested source snapshots, reports, and
tool/build captures without walking their contents. Phase-level files such as
READMEs, package verifiers, recorder scripts, and API adapters remain visible.
Nested source files inside attempts are frozen execution inputs, not active
harnesses; keep new active source with the owners listed above.

The initial read-only inventory found 36,105 files / 17,381,098,081 logical bytes:
1,368 tracked files present, 34,620 visible untracked files, and 117 already-ignored
files. Visible untracked evidence alone occupied 17,216,455,002 bytes, including
408 syscall traces totaling 11,242,867,170 bytes. The directory rule leaves only
118 shallow untracked files / 77,097,985 bytes. Two large shallow preservation
inventories are also ignored by exact path:

- `pt8/preservation-before.json`: 21,986,695 bytes.
- `pt8-workloads/preservation-baseline.json`: 31,902,338 bytes.

Together these rules leave 116 shallow untracked files / 23,208,952 bytes at that
inventory point, before subsequent documentation edits. These are inventory
observations, not a size limit or a requirement to rewrite historical evidence.

Ignoring evidence does not delete it or back it up. Already-tracked curated
payloads remain tracked, including the SRAM portable replay archive and retained
resource-realization packages. Deliberately curated new packages can be tracked
explicitly with a narrowly scoped forced add; review their complete inventory
first. Do not blanket-stage raw captures or alter historical paths, hashes,
receipts, failed attempts, or frozen verifier inputs to match today's layout.

## Local stores versus disposable builds

- `/_build*/`: disposable generated Dune build trees.
- `/.dev/`: local dependency/provider installations, generations, receipts and
  locks; development stores may also contain durable daemon history, artifacts,
  registry state and client preferences. This is not simply a build cache.
- `/_flow_tools/`: managed installed flow tools and collateral.
- `/_flow_results/`: generated bundles, operations and flow results; these may be
  evidence worth retaining, rather than disposable compiler output.

Those root stores are already ignored. Their ignore status is a staging policy,
not a deletion policy. The acceptance rule is scoped to retained evidence here
and does not hide new source directories elsewhere in the repository.
